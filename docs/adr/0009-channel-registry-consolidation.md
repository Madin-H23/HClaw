# 渠道类型注册表收敛：批二获授权的唯一上游 refactor

上游七渠道类型以 7 值联合类型硬编码散布于主入口等巨石文件多处（含渠道清单、switch 分发、工厂注册），新增渠道需改 N 处——批二要接的微信/飞书/钉钉验证与未来渠道扩展都压在这笔债上。本决策授权对该联合类型做 expand-contract 收敛（联合→注册表单一事实源），是「上游语义零改动（改上游仅限修 bug）」纪律的**显式破例**：行为逐字节不变的纯机械重构，每一步保持全量测试绿。

**Considered Options**: ①不收敛、新渠道继续改 N 处——每接一渠扩大违例面，弃；②注册表只活在 HClaw 新模块、上游联合保留——新渠道仍须改上游，问题没解决，弃；③expand-contract 收敛（本决策）——一次性还债，之后上游对渠道数的感知收敛到注册表单点。

**Consequences**: expand 阶段注册表与旧联合并存（旧联合从注册表派生，类型系统保证一致）；contract 阶段删除旧联合残留。重构以全量测试零 diff 为验收线，不夹带任何行为变更。
